Appendix B. Decoding the scopes already on air

[[F]] The firmware derives a region's key as the first 16 bytes of SHA-256 over # plus the name, and a packet's code as the first two bytes of HMAC-SHA256 under that key over one byte of payload type followed by the payload, with the values 0x0000 and 0xFFFF moved to their neighbors. [[@fw-regionmap:L175-183; fw-tks:L4-18, L44-47]] [[F]] The analyzer exposes raw packet bytes for transport-route packets. [[@cs-packets]] I recomputed the code for each of 4,461 candidate names (every name and alias in the generator and PNW data files, the SoCal and PNW airport codes, and likely words such as county, city and channel names) and kept names that matched.

  • [[C]] How far to trust a match. A code is 16 bits, so a single packet has about a 6.8 percent chance of matching some name in a 4,461-name list by accident (4,461 divided by 65,536). Across 13 packets that predicts about 0.9 accidental matches, and exactly one appeared (rio-vista on one advert). The chance that any one name matches three independent packets from the same sender by accident is below one in a billion, so psp, san and california for the bot are solid. [[I]] us and california on the two single packets from User B each rest on one match; they are credible because both are names from the generator's root chain, and I would still call them probable.
  • [[F]] The analyzer listed about 30 more #weather posts from the same bot in the week, all with a zero second code. [[@cs-packets]] [[I]] I expect them to decode the same way and did not test them.
  • [[I]] Limits. A name outside my candidate list is invisible to this method, which is why one packet has no match. I can only see packets an observer recorded. The hop counts show how far each packet was carried to an observer and say nothing about who else heard it. [[I]] A relay does not prove the relaying repeater holds the name, because firmware older than 1.10 forwards scoped floods unchecked. [[@blog-region]]

Check it yourself. [[F]] The function below is a second, independent implementation. For each of the 12 matched packets it returns the same four hex digits that the packet carries in bytes 2 and 3. [[@own-decode]] [[F]] The analyzer stores these same packets with an empty scope name, which is its marker for a scoped packet whose name it could not resolve. [[@cs-src-db:L3270-3278]]

Python 3, standard library only
import hashlib, hmac

def code(name, raw_hex):
    b = bytes.fromhex(raw_hex)
    ptype = (b[0] >> 2) & 0x0F               # payload type from the header byte
    n = b[5]                                 # path length byte, after two 16-bit codes
    path = ((n >> 6) + 1) * (n & 0x3F)       # hash size times hop count
    payload = b[6 + path:]
    key = hashlib.sha256(('#' + name).encode()).digest()[:16]
    mac = hmac.new(key, bytes([ptype]) + payload, hashlib.sha256).digest()
    return mac[:2].hex().upper()

# code('psp', '10EF3600...') returns 'EF36', the packet's own bytes 2 and 3

Appendix C. Airtime arithmetic

[[F]] The firmware estimates airtime by calling RadioLib's time-on-air routine, and from 1.16 uses a 32-symbol preamble at spreading factor 8 and below. [[@fw-radio:L56-57; blog-116; own-toa]] [[C]] At 62.5 kHz and SF7 a symbol lasts 2.048 ms (128 divided by 62,500). The packet takes 32 + 8 + 4.25 preamble and sync symbols plus 5 symbols for every 28 bits of the quantity 8 × length + 16 − 28 + 8 + 20, rounded up.

  • [[C]] Mean airtime per sent flood: 99 / 316 = 0.313 s, consistent with packets somewhat above the 56-byte average.
  • [[E]] Route 1: 1,603 × 0.313 = 502 s received, 18.2 percent; plus 99 s sent, 3.6 percent; total 21.8 percent.
  • [[E]] Route 2: receive-to-transmit ratio 286 / 58 = 4.93; 99 × 4.93 = 488 s, 17.7 percent; plus 3.6 percent; total 21.3 percent.
  • [[I]] Both routes omit packets the radio could not decode and direct-routed traffic, so the true figure is higher. Both describe one site in one late-afternoon window.
  • [[E]] Scaling by flood rate (423 unique floods per hour in the window against a seven-day mean of 275) puts the all-day average near 14 percent. [[@cs-retx]]
