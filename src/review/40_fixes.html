[[O]] Three ways to converge, each with a cost. A. Adopt the generator's tree as it stands. The maintainer wrote it and a tool already emits it. A Conejo repeater then carries six names, three of which (us, west, california) do nothing inside an isolated SoCal, and today's psp and san users re-tag. B. Adopt the plan's airport metros and have the generator and wiki changed. This asks the maintainer to reverse his August work. C. A short flat set: socal, one metro name per MeshMapper zone, and the generator's area names for local tags. This reuses each existing vocabulary at the layer where a tool already emits it, avoids names that are prefixes of other names, and keeps a repeater to three entries. I lean to C with low confidence. Whichever is chosen, the choice belongs to the people who maintain the three tools.

Corrected rollout with gates (replaces §04)

  1. Now, independent of scoping. [[R]] Apply the WCMesh repeater settings as published (Finding 6). Ask bot owners for acknowledgement-only behavior, as the Q2 report proposes. [[@wc-q2:L39]] Check get flood.max.advert returns 8 or less on 1.16 and newer. [[@fw-rep:L907]] Design a flood.max trial (Finding 14).
  2. Phase 0, decide and measure. [[R]] One vocabulary agreed with the three tool maintainers. A firmware census. Baseline counters from at least five reference repeaters in different metros. The agreed names loaded into the analyzer's hashRegions. [[@cs-src-cfg:L400-404]] The raw baseline archived as a file. Gate: all five exist in writing.
  3. Phase 1a, tags only. [[R]] Repeater owners add the metro tag and socal with flooding allowed. No default scope. The wildcard stays allowed. Gate, per metro [[O]]: a test message scoped to the metro and sent from one edge is heard at every observer in that metro on three separate days.
  4. Phase 1b, default scope on repeaters. [[R]] region default <metro> only in metros that passed the gate. Check: each repeater's next flood advert still reaches an observer.
  5. Phase 2a, machines. [[R]] The MeshMapper administrator sets the Wardriving Scope for that zone, and bot owners set the bot radio's default scope to the metro. [[@mm-admin; blog-default]] Gate [[O]]: MeshMapper coverage for the zone is unchanged week over week, and relays per flood on #wardriving and the bot channels have fallen.
  6. Phase 2b, people. [[R]] Local channels may be scoped to the metro by their users. Companion default scope moves to socal only after the wide gate [[O]]: a socal-scoped message reaches every observer site, and the census shows at least 95 percent of repeaters carrying socal. Emergency and alert channels stay unscoped through this phase.
  7. Phase 3, containment, optional. [[R]] On 1.16 and newer, step flood.max.unscoped down from 12, one step at a time (12, 8, 5), holding each for 30 days and reversing if delivery tests fail. Consider region denyf * only after the unscoped share of flood-routed channel messages has stayed under 5 percent for 30 days [[O]], and only by agreement across the whole mesh. [[F]] The Dutch guide warns that region denyf * "only works reliably from v1.15 onwards". [[@nl-guide:L56]]

Corrected cookbook (replaces the §05 and §07 command blocks)

[[F]] Five rules first. (1) Names are lower case, at most 29 bytes, letters, digits and hyphen. [[@blog-region]] (2) No name may be the beginning of another name, because the CLI matches by prefix. [[@fw-regionmap:L218-231]] (3) Before any allowf, denyf or default, run region get <name> and check that the reply echoes exactly the name you meant. [[@fw-cli:L1086-1097]] (4) region default saves everything at once and invents a region from a typo. [[@fw-cli:L1109-1128]] (5) [[R]] Work over USB or from direct radio range, and confirm you can still log in before you leave.

Corrected pilot protocol (replaces the §07 criteria)

[[R]] Run two pilots, because they answer different questions.

Pilot A, mechanics, Conejo Valley.

  1. Partners. At least three contiguous repeaters: SkyNet, one neighbor toward Los Angeles, and NP-CAM Grade, which carried SkyNet's advert to the Camarillo observer in one hop. [[@cs-advert]] Ask the analyzer's maintainer to load the test names first.
  2. Instrument. On-node counters on each pilot repeater, read before and after: flood packets received and sent, duplicates, receive errors, transmit and receive airtime. [[@fw-stats:L28-50; own-telemetry]] The analyzer is the secondary check.
  3. Configure. Tags only, using the block for each node's firmware. No default scope yet.
  4. Test 1, positive control. Send a message scoped to the pilot tag from one end of the cell. Pass: a companion at the other end, two hops away, receives it.
  5. Test 2, negative control. The same message must not be received by a companion one hop outside the cell, and the analyzer must show no path that leaves the pilot nodes. If it leaks: suspect a pre-1.10 repeater and record which one. [[@blog-region]]
  6. Test 3, unscoped control. An unscoped message sent in the same minute still arrives outside the cell.
  7. Test 4, the app and capitals. Type the scope in mixed case in the app and repeat Test 1. This is the case test that matters.
  8. Test 5, default scope. Set the default on one pilot node, send advert, and count the observations the analyzer records against the 64 it recorded for SkyNet's unscoped advert on 11 October. [[@cs-advert]] Prediction: far fewer, possibly none.
  9. Test 6, direct messages. With one companion's default scope set to the pilot tag and the other unset, exchange direct messages both ways and note which acknowledgements arrive.

[[I]] Pilot A can prove the mechanism and expose leaks. It cannot show a load reduction, because a few test messages are invisible against roughly 6,600 floods a day. [[@cs-retx]]

Pilot B, load, one MeshMapper zone. [[R]] Pick the zone with the best repeater coverage of its tag, set the Wardriving Scope for that zone only, and compare relays per #wardriving ping and MeshMapper coverage results for two weeks before and after. [[@mm-admin; cs-retx]] This is the pilot that can show the benefit, and it needs the MeshMapper administrator.
