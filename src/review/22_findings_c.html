The cookbook works on one firmware generation and walks into four CLI traps

High

[[P]] Every repeater example uses region def, with "Target firmware 1.16+ (minimum 1.15)". [[@plan:§04, §05]] [[P]] The Phase 4 block is four lines: region denyf *, a comment line starting with #, set flood.max.unscoped 3, and region save. [[@plan:§05]] [[P]] A two-repeater bench test of case behavior is a "hard gate". [[@plan:§04]]

What the sources show

  • [[F]] region def is new in 1.16.0. [[@blog-116]] [[F]] On 1.15 the equivalent is one region put per name, which answers "OK - (flood allowed)". [[@fw-v115:L971-981]] [[F]] On 1.14.1 and earlier, region put leaves the new region denied and there is no region default. [[@fw-v1141:L1234-1245; blog-default]] [[I]] The plan names 1.15 as its minimum and gives no commands that run on it.
  • [[F]] WCMesh asks for 1.15.0 or newer and notes that many repeaters are "physically hard to reach (e.g. mountain top) to upgrade". [[@wc-q2:L95; wc-multibyte:L16]]
  • Trap 1, the Phase 4 block. [[I]] Pasted as written it applies both alternatives, the strict one included. [[F]] The comment line is sent to the CLI as a command; unrecognized input gets "Unknown command". [[@fw-cli:L444]] [[F]] set flood.max.unscoped saves itself, so the trailing region save belongs to the denyf. [[@fw-cli:L632-639, L1065-1069]]
  • Trap 2, prefix matching. [[F]] allowf, denyf, get, home, default and the parent argument of put look a name up by prefix: an exact match wins, otherwise the last region whose name begins with what was typed. [[@fw-regionmap:L218-231; fw-cli:L1070-1116, L1134]] [[I]] The <metro>-<place> pattern creates names where one is the prefix of another. On a repeater that holds oxr-conejo but not oxr, region denyf oxr answers "OK" and denies oxr-conejo, and region default oxr makes oxr-conejo the default. The same applies to socal and the reserved socal-em.
  • Trap 3, region default. [[F]] It creates the region if no name matches, turns flooding on for it, and saves the whole region table at once. [[@fw-cli:L1109-1128; blog-default]] [[I]] A typo becomes a new saved region and the node's adverts go out under it. Any half-finished edit in memory is saved with it.
  • Trap 4, the confirmation step. [[F]] Every region reply, including the tree printed by bare region, is cut at 160 characters. [[@fw-cli:L1055, L1062, L1172]] [[F]] The table holds 32 names; region def stops at the first failure and leaves the earlier names in place. [[@fw-regionmap-h:L7-8; fw-cli:L1027-1028; fw-docs-cli:L865]] [[F]] It also never clears what was already there, and removal is by exact name and fails while a region has children. [[@fw-docs-cli:L845; fw-cli:L1146-1157; fw-regionmap:L259]] [[I]] The plan has no inventory step before configuring and trusts a listing that can be truncated. Canada's guide has a "Clear any old regions" step. [[@ca-onqc:L437]]
  • The case question is already answered for repeaters. [[F]] The firmware accepts any byte from A upward in a name, compares names with an exact string match, and hashes the literal name into the key. [[@fw-regionmap:L52-55, L175-183, L207-216; fw-tks:L44-47]] [[F]] The firmware author's rule is "Only lower case alpha-numeric chars, and - (hyphen)". [[@blog-region]] [[I]] So OXR and oxr are different regions on a repeater, and no bench test is needed to learn that. [[F]] The app computes the key itself and hands it to the radio. [[@fw-comp:L1929-1949]] [[U]] Whether the app lowercases what a user types is the part I could not check, and that is what a bench test should target.

Correction

[[R]] Replace the cookbook with the version-specific blocks in Corrected cookbook. Split Phase 4 into two separate blocks that cannot be pasted together. Add the rule "no region name may be the beginning of another region name", which rules out <metro>-<place> and socal-em in their current form. Change the Phase 1 gate from "prove case behavior" to "type the scope in mixed case in the app and confirm a lowercase-tagged repeater still forwards it".

Structural gaps in the template: roles, straddling communities, LGB, and whose geography this is

Medium
  • Role C does not bridge. [[P]] Boundary repeaters carry "both adjoining metro codes plus <wide>" and are called "genuine bridges". [[@plan:§03]] [[F]] A scoped packet carries one code. [[@fw-rep:L997-1005]] [[I]] A dual-tagged repeater relays each metro's floods one hop further, into ground where the next repeater holds only the other metro's tag and drops them. Only the wide scope crosses. The firmware author's own example uses dual tags for overlap coverage in "boundary areas". [[@blog-region]] [[R]] Rename the role "overlap repeater" and say what it does: it gives users in the seam coverage under either metro's scope.
  • No construct for a community that straddles a line. [[F]] The PNW plan has cross-border community tags that "sit alongside your state ancestry". [[@pnw-rollout:L113]] [[F]] The Pomona Valley lies between the San Gabriel and San Bernardino valleys and "acts as a section of the border between Los Angeles County and San Bernardino County". [[@geo-pomona]] [[F]] WCMesh lists a #claremontupland channel, "Local chat for Claremont Upland area". [[@wc-channels:L87-88]] [[I]] The plan would cut that community between lax-sgv and ont-west. [[R]] Allow a local tag that belongs to no metro, carried by the repeaters that serve the community.
  • lgb fails the plan's own rule. [[P]] "Follow RF propagation, not counties", yet Long Beach is a metro with no sub-regions whose "RF overlap with the LA Basin is honest". [[@plan:§03, §06]] [[F]] One observer of 58 is tagged LGB, and MeshMapper lists no LGB zone. [[@cs-observers; mm-socal]] [[R]] Fold Long Beach into lax unless Long Beach operators ask otherwise.
  • "The analyzer's geography" is whatever each observer operator typed. [[F]] An observer's region code comes from its own uploader configuration. [[@cs-readme:L190-191]] [[F]] 25 of the 58 observers are tagged LAX and 18 SAN. The LAX set includes observers positioned in Santa Ana (33.73, -117.86), Riverside (33.94, -117.38) and the Victor Valley (34.55, -117.14), and one named "NW Bakersfield MQTT". [[@cs-observers]] [[I]] The labels are weak evidence for an eight-metro standard, and the plan's decision "Ratify the airport-code metro tier? Recommendation: yes; it reuses the analyzer's familiar geography" rests on them.
  • "Ratify the 11 labels" reaches into another mesh. [[F]] BFL, FAT and MCE have no display names in the analyzer and no observers, and the Central Valley runs on a different frequency. [[@cs-regions; cs-observers; wc-radio:L12]] [[R]] Ratify SoCal names only. The Central Valley's names are for its own operators to choose.
  • Places with traffic and no cell. [[F]] #applevalley and #ramona are active, an observer sits in the Victor Valley, and the generator has victorvalley and a whole imperial county. [[@cs-channels; cs-observers; mk-data:L1174, L1248]] The plan has no high-desert or Imperial cell and lists #temecula without saying which metro it maps to.
  • socal-em is a name without a function. [[I]] Under per-name matching it behaves exactly like socal unless some repeaters allow one and deny the other, and the plan defines no such state. Reserving it adds a prefix hazard (Finding 11) for no benefit. [[R]] Drop it, or define the trigger and the repeater configuration that makes it different.

Three of the eight terrain rows put places on the wrong side of the range

Medium

[[P]] §06 presents a barrier inventory of eight rows and a schematic map, described as desk analysis. [[@plan:§06]] [[O]] Calling it desk analysis is fair warning. It is still wrong in ways a local operator will notice at once, and it cites no source.

  • [[P]] "Santa Monica Mountains | Conejo / Malibu ↔ LA Basin and SFV". [[@plan:§06]] [[F]] The eastern part of the range forms "a barrier between the San Fernando Valley and the Los Angeles Basin"; the western part separates "the Conejo Valley from Malibu". Thousand Oaks and Newbury Park are on the north slope, Malibu on the south. [[@geo-smm]] [[I]] The row pairs Conejo with Malibu and the Basin with the Valley. Both pairs sit on opposite sides.
  • [[P]] "Santa Susana Mountains / Simi Hills | Simi ↔ SFV and Conejo". [[@plan:§06]] [[F]] These are two ranges with different jobs. The Simi Hills have the Simi Valley to their north, the San Fernando Valley on their east and the Conejo Valley to the southwest. [[@geo-simi]] [[F]] The Santa Susana Mountains separate "the San Fernando and Simi valleys on its south from the Santa Clara River Valley to the north and the Santa Clarita Valley to the northeast"; Santa Susana Pass "connects the Simi and San Fernando valleys". [[@geo-susana]]
  • [[P]] "San Gabriel Mountains | LA / SGV / SFV ↔ Santa Clarita and Antelope valleys". [[@plan:§06]] [[F]] The Santa Clarita Valley has the Santa Susana Mountains "to the south and southwest" and reaches the San Fernando Valley "via Newhall Pass". [[@geo-scv]] [[F]] Newhall Pass separates the Santa Susana Mountains from the San Gabriels, which lie "between the Los Angeles Basin and the Mojave Desert". [[@geo-susana; geo-sgm]] [[I]] The San Fernando to Santa Clarita divide belongs to the Santa Susana row.
  • [[P]] "Santa Ana Mountains | Orange County ↔ Inland Empire | Hard SNA / ONT metro edge". [[@plan:§06]] [[F]] Santa Ana Canyon is "the water gap where the Santa Ana River passes between the Santa Ana Mountains and the Chino Hills", near the meeting point of Orange, Riverside and San Bernardino counties, with State Route 91 through it. [[@geo-sac]] [[I]] The edge has a low-level gap in it, which is where boundary sites would be.
  • [[P]] "Palomar / Laguna Mountains | San Diego coast ↔ East County / desert". [[@plan:§06]] [[F]] East County "commonly includes El Cajon, La Mesa, Lemon Grove, and Santee"; only a broader definition takes in the Cuyamaca and Laguna mountains and the Anza-Borrego desert. [[@geo-east]] [[I]] The suburbs most people mean by East County are on the coastal side of the mountains, so a san-east cell defined by this row mixes two RF environments.
  • [[F]] The remaining three rows are consistent with the sources I checked: the Santa Ynez Mountains with the Santa Ynez River just to their north, the Conejo Grade linking the Conejo Valley with the Oxnard Plain, and the Cajon and San Gorgonio passes on either side of the San Bernardino Mountains. [[@geo-ynez; geo-grade; geo-cajon; geo-gorgonio]]
  • [[F]] On the map, the lgb label is drawn south of sna-central; at least seven labels overlap or are hidden behind others (sba-coast, oxr-plain, oxr-conejo, lax-sfv, ont-riv, sna-central, san-east); and the caption is clipped at both edges. [[@own-image]] [[F]] The generator's coordinates put Long Beach at 33.77, -118.19 and Santa Ana at 33.75, -117.87. [[@mk-data:L1075-1080, L1124-1129]] [[C]] Long Beach is about 30 km west of Santa Ana at almost the same latitude.

Correction

[[R]] Use the corrected barrier table. Replace the bitmap with a drawn map (the current image is 96 percent of the file's size) or remove it until operators have marked real boundary sites on it.

Missing levers, missing census, and a baseline that measures noise

Medium
  • The hop limit. [[F]] flood.max defaults to 64 hops. [[@fw-rep:L905]] [[F]] Canada sets 16 and says "16 hops has to be enough". [[@ca-onqc:L519, L885-887]] [[I]] A cap needs no namespace, no coordination and no new firmware, and it trims wandering duplicates before it touches first arrivals. The plan never mentions it. [[R]] Propose a trial value between 20 and 24 on a few high sites and measure delivery before going lower.
  • The advert hop limit. [[F]] SkyNet's advert was observed over paths up to 11 hops, past the default limit of 8. [[@cs-advert; fw-rep:L907]] [[I]] Some forwarders are on pre-1.16 firmware or have raised the limit, which is itself a census data point.
  • No firmware census. [[F]] What a repeater can do with a scope depends on its version: before 1.10 it forwards scoped floods unchecked; 1.10 and 1.11 expect names that start with #; 1.12 to 1.14 match plain names but need allowf and have no default scope; 1.15 adds the default scope; 1.16 adds region def and the unscoped and advert hop limits. [[@blog-region; fw-v111:L123-134; fw-v112:L173-184; fw-v1141:L1234-1245; blog-default; blog-116]] [[F]] Neither tool publishes firmware versions, so the proxy is path-hash capability, which needs 1.14 or newer. The analyzer's tally is 515 multi-byte repeaters of 783, with 263 on one byte that could be running anything. [[@cs-hash; wc-multibyte:L29-31]] [[F]] MeshMapper's multibyte board shows 574 of 655 repeaters in its Los Angeles zone (87.6 percent) and 247 of 283 in San Diego (87.3 percent). [[@mm-board]] [[U]] The second assistant's memo reports the other three zones from the same board as Oxnard 114 of 133, Santa Barbara 110 of 139 and Palm Springs 23 of 40; I could not load those rows. [[@memo]] [[I]] If that last figure is right, the Coachella Valley is the zone furthest behind and also the one with a repeater already sending scoped adverts. [[R]] Make a version census a Phase 0 deliverable.
  • Two tools, two fleet sizes. [[C]] MeshMapper's Los Angeles and San Diego zones alone hold 938 repeaters, more than the 806 the analyzer lists for all of SoCal. [[@mm-board; cs-stats]] [[F]] MeshMapper's default marks a repeater inactive only after 30 days unheard. [[@mm-admin]] [[I]] The two tools probably count over different windows, so any percentage gate in the rollout has to name which tool's denominator it uses.
  • Census tools that already exist. [[F]] The analyzer's scope audit holds captured region lists for 30 repeaters: 27 declare the wildcard only, none declares a named region, and 3 report a state it calls "no-flood". [[@cs-audit]] [[I]] A repeater that denies the wildcard and holds no named region forwards no floods at all, so those three deserve a look by their owners. [[F]] MeshMapper has an optional scope-discovery mode that asks each repeater which scopes it carries, and a "Scopes to Monitor" list. [[@mm-admin]] [[U]] The memo reports that MeshMapper's leaderboard already counts scoped repeaters per zone: 2 in Los Angeles, 1 in Palm Springs, 1 in San Diego and none in Oxnard or Santa Barbara. [[@memo]] [[F]] The plan lists meshcore-bot v1.1.0 as "census tooling" in its references and never uses it. [[@plan:§10; bot-release]]
  • The baseline is mostly noise. [[F]] Of the 58 most recent transport-route packets on 13 October, 12 had a second transport code of zero, which is what the firmware always sends, and they came from five senders. The other 46 had a non-zero second code or all-zero bytes, payload types such as "UNKNOWN (13)", and paths up to 63 hops. [[@cs-packets; fw-rep:L997-1005; fw-comp:L489-497]] [[I]] Those 46 are corrupted frames that happened to parse. About four fifths of what the analyzer counts as "scoped" is bit errors, and the plan's baseline of 69 scoped packets measures that plus three or four early adopters.
  • No decision process. [[P]] "Nothing here is adopted until the community says so", followed by twelve open questions with no owner, venue or date. [[@plan:§09, §10]] [[R]] Name who decides each one and where.

Correction

[[R]] Add the hop limit and the census to Phase 0, and replace the "unscoped share" metric with the outcome measures in Measures that can fail.
